# Measurement setup for knowledge.magicworksitsolutions.com

## Objective

Track the MagicWorks Knowledge & Resource Centre separately enough for search and content analysis, while preserving one coherent customer journey across the MagicWorks main site and knowledge subdomain.

## Google Search Console

Create a separate **URL-prefix property**:

`https://knowledge.magicworksitsolutions.com/`

This property is used for:

- knowledge-centre clicks, impressions, CTR and average position;
- indexing and URL inspection;
- knowledge-centre sitemap submission;
- page-level search performance;
- issue diagnosis specific to the subdomain.

Keep the existing main-site Search Console property.

If a root Domain property for `magicworksitsolutions.com` is also maintained, it can be used for aggregate reporting across all subdomains.

## Google Analytics 4

Do **not** create a second GA4 property unless a future governance requirement demands complete data separation.

Use the existing MagicWorks GA4 property and create a separate **Web data stream**:

- Website URL: `https://knowledge.magicworksitsolutions.com`
- Stream name: `MagicWorks Knowledge Centre`
- Enhanced measurement: enabled unless a specific measurement requirement says otherwise

This produces a dedicated `G-...` Measurement ID for GitBook while keeping main-site and knowledge-centre analysis within the same GA4 property.

Why:

- one business/customer journey;
- easier cross-subdomain analysis;
- separate stream-level implementation;
- avoids unnecessary duplicate GA4 properties.

GitBook's Google Analytics integration must use the dedicated knowledge-centre `G-...` Measurement ID, not the main site's GTM container ID `GTM-W75DJC`.

## Bing Webmaster Tools

Create a separate site:

`https://knowledge.magicworksitsolutions.com/`

Preferred setup:

1. verify the knowledge subdomain in Google Search Console;
2. use Bing Webmaster Tools' **Import from Google Search Console** option;
3. select the verified Knowledge Centre property;
4. submit/confirm the GitBook sitemap.

Keep the existing MagicWorks main-site entry.

## Sitemap

After publication, use the exact sitemap URL generated by GitBook.

Do not guess the sitemap path before publication.

Submit the same published sitemap to:

- Google Search Console Knowledge Centre property
- Bing Webmaster Tools Knowledge Centre site

## Microsoft Clarity

Optional.

If behaviour recordings/heatmaps are required for the Knowledge Centre, use a separate Clarity project or a deliberately configured existing project. Only add Clarity if GitBook's plan/integration method supports the implementation cleanly and consent/privacy requirements are satisfied.

## Reporting model

### Main site reporting

Use the existing main-site properties/streams for:

- commercial landing pages;
- service pages;
- forms;
- primary lead-generation journeys.

### Knowledge Centre reporting

Use the separate GSC/Bing properties and dedicated GA4 web stream for:

- organic discovery;
- AI/referral discovery;
- knowledge landing pages;
- search/AI-search usage;
- knowledge-to-service clicks;
- knowledge-to-contact clicks;
- resource downloads;
- assisted conversions.

## Attribution rule

Do not use internal UTM parameters between:

- `magicworksitsolutions.com`
- `knowledge.magicworksitsolutions.com`

Both are owned MagicWorks web properties.

Use GA4 stream/domain configuration and events instead.
